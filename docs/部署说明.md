# 智途 AI 部署与提交说明

## GitHub Pages

1. 将当前项目上传到自己的 GitHub 仓库，保留 `LICENSE`，使用 `main` 分支。GitHub Free 可用于公开仓库的 Pages。
2. 仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 推送 `main`，或在 **Actions → Build and deploy Zhitu AI → Run workflow** 手动运行。
4. 工作流依次运行智途功能检查、上游算法回归、TypeScript 检查、Vite 构建与 Pages 部署。
5. 在 Pages 设置页或部署任务中复制实际返回的在线网址。用未登录浏览器测试主要页面，确认可访问后再向老师提交。

常规项目网址形如 `https://<用户名>.github.io/<仓库名>/`。这是格式示例，不是已经发布的真实地址。无需自购域名或租用独立服务器；不同地区与校园网络的访问体验需要实际验证。

## 备用静态托管

执行 `npm ci` 和 `npm run build` 后，上传 `dist` 文件夹内容即可。Cloudflare Pages 可采用 Git 集成或 Direct Upload；构建命令为 `npm run build`，输出目录为 `dist`。若使用压缩包，解压后应直接看到 `index.html`、`assets/` 和 `logo.svg`。

不要上传 `node_modules`、个人导出的 JSON 档案或本地环境文件。

## 提交与展示

默认展示可操作的示例档案，页面有明确标注。真实使用从“我的档案 → 建立我的空白档案”开始。完成测评后选择职业，再调整学习时间、勾选任务与生成报告。

数据保存在访问者自己的浏览器中；老师打开网址不会看到你在另一台电脑上填写的个人档案。需要展示个人规划时，同时提交导出的 PDF 报告，或在演示电脑中导入你的 JSON 档案。

## 主要配置

- `vite.config.ts`：相对路径 `base: './'`。
- `src/zhitu/App.tsx`：HashRouter，静态站点无需服务端重写。
- `.github/workflows/pages.yml`：检查与部署。
- `src/zhitu/data.ts`：中文职业、技能、兴趣题、学习资源与任务。
- `public/LICENSE.txt`：部署包内保留上游 MIT 声明。

参考：[GitHub Pages 自定义工作流官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)。
